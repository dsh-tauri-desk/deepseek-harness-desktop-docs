Tauri packages the React frontend, Rust backend, and bundled resources into native installers. GitHub Actions runs the release pipeline.

## Local build

Prepare the toolchain in [Development setup](./setup), then run:

```bash
pnpm install --frozen-lockfile
pnpm build:plugins
pnpm typecheck
pnpm lint
node node_modules/vitest/vitest.mjs run --project unit
pnpm tauri build
```

`pnpm tauri build` uses `pnpm build` to build plugins and the frontend before compiling and bundling Rust. Complete the E2E and Rust checks in [Testing and quality checks](./testing); platform bundles require a compatible OS and its signing tools.

## Current release artifacts

The current desktop source is `0.22.x`; the latest preview is [`v0.20.1-beta.4`](https://github.com/dsh-tauri/deepseek-harness-desktop/releases/tag/v0.20.1-beta.4). The stable [`v0.22.1`](https://github.com/dsh-tauri/deepseek-harness-desktop/releases/tag/v0.22.1) provides these installers:

| Platform | Release assets |
| --- | --- |
| Windows x64 | `.exe`, plus English and Simplified Chinese `.msi` installers |
| macOS Apple Silicon | `aarch64.dmg` |
| macOS Intel | `x64.dmg` |
| Linux x64 | `.AppImage`, `.deb` |

Four additional `_Bundle` offline packages (`.exe`, `.deb`, and two `.dmg` files) embed the managed Node.js runtime, pnpm, and core so the first launch needs no network. Do not label a prerelease stable or infer unreleased architectures from source code or CI targets.

## Release flow

The [release workflow](https://github.com/dsh-tauri/deepseek-harness-desktop/blob/main/.github/workflows/release.yml) runs for a `v*` tag, a merged `release/*` PR from the same repository, or a manual trigger. Manual runs produce test prereleases.

1. Align package, Cargo, and Tauri versions, release notes, and both documentation languages.
2. Complete frontend type checking, linting, the three test layers, and cross-platform Rust checks.
3. Build Windows, both macOS architectures, and Linux x64 artifacts in parallel; verify signing, notarization, and installation behavior.
4. A single publishing job gathers successful outputs. Prereleases are marked accordingly; only stable releases update latest.

<Warning>
  Never expose signing certificates, notarization credentials, or update keys in logs,
  documentation, pull requests, or local fixtures. Use repository secrets and the
  established release workflow.
</Warning>

The current public release provides Linux x64 artifacts only; do not label Linux ARM as
supported until matching artifacts are built and verified.
