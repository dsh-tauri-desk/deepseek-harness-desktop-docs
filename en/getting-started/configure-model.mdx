Configure at least one model provider before starting a task. Model settings belong to the embedded Harness interface, not the desktop **Configuration** dialog.

<Frame>
  <img src="/images/en/model-settings.png" alt="Harness model settings with the DeepSeek provider card" />
</Frame>

## Add DeepSeek

<Steps>
  <Step title="Open model settings">
    Open **Settings → Models** in the Harness sidebar. The desktop extends this page through the built-in [DSH Tauri Model](../built-in-plugins/dsh-tauri-model) plugin.
  </Step>
  <Step title="Save credentials">
    Enter an API key from the [DeepSeek Platform](https://platform.deepseek.com/) in the DeepSeek card and save it.
  </Step>
  <Step title="Select a model and test">
    Return to the session composer, choose an available model and workspace, and send a small task such as summarizing the repository. If it fails, check credentials, balance, endpoint, and model name first.
  </Step>
</Steps>

<Warning>
  Never put API keys in chat messages, repositories, screenshots, or issues. Model requests send the necessary context to your chosen provider; check its privacy policy and data scope before processing sensitive code.
</Warning>

## Other providers and custom endpoints

| Entry point | What you need |
| --- | --- |
| **Add provider** | An installed provider plugin, credentials, and available models |
| **Add custom provider** | A stable lowercase Provider ID, base URL, protocol, credentials, and at least one model |

Configure context length, output limits, image input, and thinking modes only when the endpoint supports them. See [DSH Tauri Model](../built-in-plugins/dsh-tauri-model) for local or company gateway compatibility options.

For upstream provider semantics, see the [model configuration guide](https://deepseek-harness.github.io/deepseek-harness/guide/providers). Next, explore the [desktop and Harness interface](../guides/interface).
