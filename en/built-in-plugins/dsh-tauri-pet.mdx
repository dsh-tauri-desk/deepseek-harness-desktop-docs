`dsh-tauri-pet` provides Pets and Codex tabs in Harness settings and controls a separate transparent, frameless pet window through the [`dsh-tauri`](./dsh-tauri) bridge. Always-on-top and positioning behavior depend on the window system.

## Select and enable a pet

<Steps>
  <Step title="Open pet settings">Open the pet section in Harness settings. Pets shows presets and local Chat pets; Codex shows local Codex pets and the ZIP import entry.</Step>
  <Step title="Choose a pet">A preset card's enable action selects and enables the pet. Use the selection action for local pets. Deselecting a pet also closes an enabled window.</Step>
  <Step title="Adjust or close">Size ranges from 50–200%. The Pets tab and the menu containing Settings offer enable / close actions. Closing persists the disabled state, so restarting does not turn the pet back on.</Step>
</Steps>

The pet displays activity states, bubbles, and movement based on sessions. It does not replace authorization or confirmation in a conversation.

## Dragging and flinging

- Grab the pet to drag its window. Releasing after a fast drag can fling it; slow movement or pausing before release does not guarantee a fling.
- Flight uses the current monitor's work area, with gravity, edge rebounds, a landing squash, and friction. Grabbing the pet again stops flight immediately.
- This interaction belongs to a single native pet window, without collisions between pets. Positioning and flinging remain subject to window-system limits.

## Resource sources

| Source | How it loads | Location or definition |
| --- | --- | --- |
| Preset | Uses remote configuration and media directly, without a download, extraction, or local installation step. | `pets.built-in` in `src-tauri/resources/manifest.jsonc`; entries provide `config`, `uri`, `ext`, `kind`, and `size`. |
| Chat | Reads the local pet directory when queried, rather than using a fixed preset list. | The current DSH data directory's `pets` subdirectory, default `~/.dsh/pets`. |
| Codex | Reads the local directory, or imports a `.zip` from the Codex tab. | `$HOME/.codex/pets`. |

Opening settings rereads the catalogs. Invalid local manifests are skipped. An invalid atlas may leave a placeholder thumbnail but cannot load as a working pet. ZIP imports write to the Codex directory and identify pets by their manifest ID. Duplicate IDs are rejected rather than overwriting existing pets.

## Create your own pet

The plugin provides the `hatch-dsh-pet` skill under its own `providerName: dsh-tauri-pet`, without replacing other skill providers.

1. The creation entry requires an available project workspace. It opens or reuses a blank session and prefills a `/hatch-dsh-pet` request. Review the draft before sending it.
2. The skill guides the Agent through a video-material workflow: a 10-second green-screen video for each action, followed by keying, normalization, and atlas baking. This requires an external AI video tool and material-processing tools such as Python 3, ffmpeg, numpy, and scipy. The plugin does not provide a video-generation service itself.
3. Deliver the result under `$DSH_HOME/pets/<petId>/`: `pet.json` plus a PNG / WebP atlas. Atlases have 8 columns and support 9 rows for v1 or 11 rows for v2; use v2 for new pets. After validation, reopen settings to select the pet, without restarting.

Local custom pets do not load video packages directly. Remote video presets and local atlases are separate resource paths. Do not import the upstream `dsh-pet` video directory or plugin package as a local Chat pet.

## State and platform limits

- The enabled switch is saved in desktop settings; closing destroys the window. Both `enabled` and `visible` derive from this switch. The latter is not an independent real-time window-visibility probe.
- Native Wayland cannot guarantee pet positioning or always-on-top behavior. Force XWayland applies to the whole app, requires a restart, and may affect scaling and input methods.
- Preset assets require network access. Local Chat and Codex pets load from local resources.

<Warning>
  Use only trusted remote assets and ZIP packages. Harness and plugins can execute local code and access local files; profiles are not operating-system sandboxes.
</Warning>

## Client bridge

State and selection use `get_pet_status`, `set_pet_enabled`, `set_active_pet`, and `set_pet_size`. Resources use `list_pets`, `list_preset_pets`, `get_pet_asset`, and `import_pet`. Native commands run through the desktop's allowlisted bridge; ordinary browsers are not guaranteed native pet-window support.
