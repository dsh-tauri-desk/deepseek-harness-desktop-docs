## Project positioning

| Project | Desktop stack | Main tradeoff |
| --- | --- | --- |
| This project | Tauri 2 + React; separate Harness service | First-party desktop additions and runtime management; community plugins are optional |
| anywhere-labs/dsh-desktop | Electron; the desktop is a DSH/Cordis plugin | Plugin composition, Profile setup, and Agents Anywhere phone control |
| dataelement/dsh-desktop | Electron | Local-first, portable Agent presets, PPT, and a paired phone bridge |
| DSH-EAC/DSH-Desktop-EAC | Tauri 2 | Integrated distribution with more preinstalled enhancements and recovery tools |

Framework names are not performance rankings. Size, memory, and responsiveness also depend on runtimes and plugins; this page has no common benchmark.

## Management, plugins, and recovery

This project uses the v0.20.0-beta.1 manifest. EAC's README feature list covers v5 and says remaining v5 bugs will no longer be fixed; it does not establish v6 Beta capabilities.

| Comparison | This project | anywhere-labs | dataelement | EAC |
| --- | --- | --- | --- | --- |
| Profiles / runtime | Native Profiles; multiple cores, local `dsh` reuse, CLI registration | Profile wizard/switching; pinned Harness | Preserves Profile data; pinned Harness | v5 separate `web-desktop` Profile; independent core updates/rollback |
| Plugin strategy | First-party built-ins; `dshmarket` and others are optional presets | Desktop as a plugin; bundled community market | Harness plugins; third-party plugins installed as needed | v5 bundled enhancements and unified market |
| Distinctive management | Skills/source management and MCP configuration: `dsh-tauri-extension` | Profile settings and plugin CLI | `.dshpreset` import/export, model providers, PPT | v5 visual MCP and configuration migration |
| Worktree / scheduling | Session Git Worktrees; scheduled runs and history | Not confirmed | Not confirmed | Not confirmed |
| Plugin failure recovery | Identifies implicated plugins and guides removal | Recovery assistant | Diagnostics; non-destructive Safe Mode | v5 snapshots, health checks, repair/rollback |

- This project recommends core `0.2.0-rc.2`, minimum `0.1.5-rc.1`; anywhere's current three channels pin `0.2.0-rc.2`.
- dataelement's manifest and v0.10.0 release notes use `0.1.7-rc.2`; its README still says rc.1. Use the version manifest.
- Current IDs here include `dsh-tauri-scheduler`, `dsh-tauri-archive`, and `dsh-tauri-model`; Beta adds native notifications through `dsh-tauri-notification`.

## Different remote-access mechanisms

| Mechanism | This project | anywhere-labs | dataelement | EAC |
| --- | --- | --- | --- | --- |
| SSH remote host | Built-in `dsh-tauri-ssh`; connects to remote `dsh web` through a loopback tunnel | Not confirmed | Not confirmed | Not confirmed |
| Phone continuation | Built-in paired bridge not confirmed; check third-party presets separately | Agents Anywhere (since 2.0.9) | Separate paired bridge: LAN / temporary internet tunnel | v6 Beta.1 notes mention a phone bridge; formal line not confirmed |

- SSH runs Harness on a remote host; phone bridges continue desktop sessions. They are not the same kind of “remote support.”
- anywhere's browser-opening option does not change the bind address; separately enabling LAN exposes an unauthenticated endpoint. Use only fully trusted networks.
- dataelement keeps Harness on a random loopback port; internet pairing needs a password, and disconnecting the phone invalidates its mobile session.

## How to choose

- For multiple cores, first-party panels, Worktrees, scheduling, or SSH hosts, start with this project and check the formal/Beta channel.
- For a plugin-composed desktop and Agents Anywhere, consider anywhere; for portable presets, PPT, and paired phone access, consider dataelement.
- For a more extensively preinstalled toolkit, consider EAC; distinguish v5 formal, v6 Beta, AIO, and historical platform packages, then check recovery workflows.

<Warning>
  Harness and plugins can execute local code. Profiles, Worktrees, Safe Mode, and plugin protection are not OS sandboxes.
  Review installers, plugins, and network exposure; use OS-level isolation for untrusted work.
</Warning>
