## Project positioning

| Project | Desktop stack | Main tradeoff |
| --- | --- | --- |
| This project (dsh-tauri) | Tauri 2 + React; separate Harness service | First-party desktop additions and runtime management; community plugins are optional |
| anywhere-labs/dsh-desktop | Electron; the desktop is a DSH/Cordis plugin | Plugin composition, Profile setup, and Agents Anywhere phone control |
| dataelement/dsh-desktop | Electron | Local-first, portable Agent presets, PPT/Office, and a paired phone bridge |
| DeepSeek official desktop | Electron; bundled full Harness Web UI and Host | Official public preview; desktop and core update together, with plugins enabled as needed |

Framework names are not performance rankings. Size, memory, and responsiveness also depend on runtimes and plugins; this page has no common benchmark.

## Management, plugins, and recovery

This project uses v0.22.1 and `main@618a2edd`; community clients are checked against the release tags above. The official column distinguishes public preview downloads from current desktop source.

| Comparison | This project | anywhere-labs | dataelement | DeepSeek official |
| --- | --- | --- | --- | --- |
| Profiles / runtime | Native Profiles; multiple cores, local `dsh` reuse, CLI integration | Profile wizard/switching; pinned Harness | Preserves Profile data; pinned Harness | Dedicated `desktop` Profile; core follows desktop updates, optional CLI registration |
| Plugin strategy | 12 first-party built-ins; `dshmarket` and others are optional presets | Desktop as a plugin; bundled community market | Harness plugins; third-party plugins installed as needed | Shared Harness plugin manager; Creator mode builds plugins |
| Distinctive management | Extension's first tab reuses the official plugin manager when available; Skills/sources and MCP management | Profile settings and plugin CLI | `.dshpreset` import/export, model providers, PPT/Office, workbench market | Plugin management, execution traces, and developer tools |
| Worktree / scheduling | Session Git Worktrees; scheduled runs and history | Not confirmed | Not confirmed | Worktrees not confirmed; scheduling requires enabling a plugin, off by default |
| Plugin failure recovery | Identifies implicated plugins, offline removal, and a separate safe Profile | Recovery assistant | Diagnostics; non-destructive Safe Mode | Native recovery dialog; disable third-party plugins, back up Profile patch, and restart |

- This project recommends core `0.2.0-rc.2`, minimum `0.1.5-rc.1`; all three published anywhere packages pin `0.2.0-rc.2`. Current `master` Beta/Next manifests now use `0.2.1-alpha.1`, which does not mean those installers have upgraded.
- dataelement v0.11.0 uses `0.2.0-rc.2`. Workbenches, including the market, are off by default and require enabling in General settings; Windows/macOS bundle a Python runtime for Office authoring.
- Current built-ins here include `dsh-tauri-mobile-ui` and `dsh-tauri-notification`; native notifications are no longer Beta-only.
- The official desktop source manifest currently says `0.2.1-alpha.1`; the download page's `latest` links do not label the installer version, so this page does not treat the source version as the installer version. Desktop and CLI share product data but keep plugin activation and executable dependencies separate; this is not multiple-core switching.

## Different remote-access mechanisms

| Mechanism | This project | anywhere-labs | dataelement | DeepSeek official |
| --- | --- | --- | --- | --- |
| SSH remote host | Built-in `dsh-tauri-ssh`; connects to remote `dsh web` through a loopback tunnel | Not confirmed | Not confirmed | Not confirmed |
| Phone continuation | Bundled mobile UI adaptation; built-in paired bridge not confirmed, optional third-party bridges need separate checks | Agents Anywhere (since 2.0.9) | Separate paired bridge: LAN / temporary internet tunnel | Not confirmed |

- SSH runs Harness on a remote host; phone bridges continue desktop sessions. `dsh-tauri-mobile-ui` is a UI adaptation, not a native phone installer or a pairing/public bridge.
- anywhere's browser-opening option does not change the bind address; separately enabling LAN exposes an unauthenticated endpoint. Use only fully trusted networks.
- dataelement keeps Harness on a random loopback port; internet pairing needs a password, and disconnecting the phone invalidates its mobile session.

## How to choose

- For multiple cores, first-party panels, Worktrees, scheduling, or SSH hosts, start with this project and check the channel and standard/Bundle assets.
- For a plugin-composed desktop and Agents Anywhere, consider anywhere; for portable presets, PPT/Office, and paired phone access, consider dataelement.
- To use the official Harness desktop preview directly, check the official download page, confirm your OS and architecture, then enable plugins as needed.

<Warning>
  Harness and plugins can execute local code. Profiles, Worktrees, Safe Mode, and plugin protection are not OS sandboxes.
  Review installers, plugins, and network exposure; use OS-level isolation for untrusted work.
</Warning>
