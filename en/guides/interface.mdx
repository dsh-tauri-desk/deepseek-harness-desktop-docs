The **Harness workspace** inside the window handles agent tasks; the native **desktop shell** manages the local service and system integration. Choose the entry point for your task.

<Frame>
  <img src="/images/workspaces-sessions.png" alt="Desktop shell and embedded Harness workspace" />
</Frame>

## Common entry points

| Task | Where to go |
| --- | --- |
| Select a workspace, create a session, or send a task | Harness sidebar and composer |
| Switch models or manage tools, Skills, or MCP | Harness **Settings** |
| Review tool activity, approvals, and results | Current Harness session |
| Configure the app, profiles, plugins, or core | **Configuration** in the desktop title bar |
| Copy runtime logs | **Help → Run logs** |
| Check desktop updates | **Help → Check for updates** |
| View desktop version and source | **Help → About Desktop** |

The top bar also provides sidebar, back, forward, and window controls. On macOS, use the native menu and traffic-light buttons.

## Desktop configuration

<Frame>
  <img src="/images/desktop-settings.png" alt="Desktop Configuration dialog with Debug, Profiles, Plugins, and Core panels" />
</Frame>

| Panel | Purpose |
| --- | --- |
| **Application** | Service address and status, port, memory, zoom, CLI integration, launch on login, close behavior, versions, and data directory |
| **Profiles** | Create, clone, switch, back up, or delete a Harness configuration environment |
| **Plugins** | Inspect installed plugins, errors, and recovery actions; manage optional plugins |
| **Core Engine** | Download, switch, or remove compatible Harness cores |

<Note>
  Closing the main window hides it to the tray by default, leaving the service running. Change this to quit in **Application**. Profiles separate configuration and plugins; they are not operating system sandboxes.
</Note>

See [Desktop settings](./settings) for options or [Workspaces and sessions](./workspaces-and-sessions) for the task workflow.
