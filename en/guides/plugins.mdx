Plugins add tools, panels, and system integrations. Distinguish built-in plugins from optional community plugins before choosing how to install or recover them.

## Plugin types

| Type | Source and control |
| --- | --- |
| Built-in | 11 first-party desktop integrations ensured by the desktop; not a community plugin bundle |
| Preset | Six optional community plugins offered by the guide; downloaded after approval and can be updated or removed |
| Other community plugins | Installed manually or through a marketplace; check sources, compatibility, and execution capabilities first |

- See the [built-in plugin overview](../built-in-plugins/overview) for the current inventory and instructions.
- `dsh-tauri-experimental` is an optional experimental package, disabled by default and not counted among these 11 plugins.

## Optional presets

| Display name | Package ID | Initial selection |
| --- | --- | --- |
| DSH Market | `dshmarket` | Recommended, selected |
| DSH Better Sidebar | `dsh-better-sidebar` | Recommended, selected |
| DSH Rewind | `dsh-rewind-plugin` | Recommended, selected |
| DSH Bridge | `@wenbin_wb/dsh-bridge` | Recommended, not selected |
| DSH IM | `@xmanrui/dsh-im` | Recommended, not selected |
| Billion Context | `billion-context` | Optional, not selected |

Presets do not count as built-ins or suit every task. Check maintenance, network dependencies, and data handling before installing. Presets such as DSH Market use the dedicated installation flow in the first-run guide or plugin management—not a chat request to the agent.

## Install, update, and recover

1. Open desktop **Configuration → Plugins** and check the active profile, sources, versions, and errors.
2. Install trusted plugins, or upgrade and remove optional plugins as needed.
3. Restart Harness when prompted and confirm plugins load.
4. If an operation is interrupted, use the recovery entry point shown in the panel; the desktop repairs missing built-ins.

Harness `0.2.0-rc.2` is recommended; `0.1.5-rc.1` is the minimum accepted version. Compatibility rules still restrict available core and plugin versions. Preserve logs after startup failures, then use an explicit recovery action; see [Troubleshooting](../help/troubleshooting).

<Warning>
  Installing a plugin installs executable local code. Profiles are not operating system sandboxes. “Built-in,” “recommended,” and “open source” do not mean risk-free.
</Warning>

Developers can read [Plugin system architecture](../architecture/plugin-system).
