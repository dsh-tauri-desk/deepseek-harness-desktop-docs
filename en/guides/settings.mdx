Open **Configuration** in the desktop title bar. Model providers, tools, and agent behavior remain in the embedded Harness **Settings**.

## Application

| Setting or status | Purpose and when it applies |
| --- | --- |
| Service address and connection status | View the actual address; local access by default, with preferred port `3080` |
| Port | Restart Harness when prompted after saving; another available port may be used if it is busy |
| Memory limit | Use automatic management or set Harness's Node.js heap limit; restart the service after changes |
| Language and interface zoom | Adjust the desktop interface; zoom range `50%–200%` |
| CLI integration | Release builds enable the managed `dsh` shim by default; open a new terminal after changes |
| Launch on login and close behavior | Closing the window hides it to the tray by default; you can change this to quit |
| Versions, data directory, and logs | View running components, open directories, or copy diagnostic information |

The desktop has no LAN setting. Packaged-core LAN opt-in does not replace authentication or permissions; see [Data, privacy, and security](../help/data-and-privacy). See [CLI integration](./cli-integration) for PATH and shell configuration changes.

## Appearance

| Setting | Purpose and when it applies |
| --- | --- |
| Palette | Eight options: `default`, `nord`, `solarized`, `forest`, `amber`, `github`, `github-dimmed`, `github-high-contrast` |
| Terminal mode | Hides the sidebar while keeping the original fonts; the top-left sidebar button reveals it |
| Transparency and opacity | Background opacity `20%–100%`; switching native transparency needs a full app exit and relaunch, not closing to the tray |
| Keep session area opaque | In transparency mode, keeps the session and right-side areas opaque while the surrounding area shows the desktop |

## Data, network, and processes

| Entry point | Common actions |
| --- | --- |
| **Configuration → Data** | Inspect disk usage, check a destination, migrate, or roll back; available in non-debug builds, while debug forces `~/.dsh.dev` |
| **Configuration → Application → Proxy URL** | Supports `http`, `https`, `socks5`, and `socks5h`; saved changes apply to new desktop downloads, updates, and plugin-metadata requests |
| **Help → Task Manager** | Inspect the local app, Harness, and child processes by name, PID, CPU, memory, and uptime; refreshes every 2 seconds by default |
| **Configuration → Profiles → Backup** | Profile backups or a recovery export including sessions; their restore procedures differ, see [Data, privacy, and security](../help/data-and-privacy) |

- Leave the proxy empty to inherit system or environment settings. Local loopback connections stay direct; do not assume all model or plugin traffic uses this proxy.
- Only Harness child processes can be ended; Harness can also be restarted. Both interrupt affected tasks. OS-managed WebView processes may be missing.

## Profiles

First installation uses `tauri`; `web` is the built-in fallback profile. Profiles manage configuration, plugins, and patches, not operating system isolation.

1. Create or clone a profile in **Profiles**, using a short ASCII name.
2. Select it, confirm the switch, and restart the service when prompted.
3. Back up before modifying or deleting it; prefer **Restore as a new profile** to test recovery.

<Warning>
  Resetting, deleting, or restoring over a profile changes its data. Back up first and confirm the recovery scope. Profile backups do not replace workspace or complete session-data backups.
</Warning>

## Plugins and core engine

| Panel | Common actions |
| --- | --- |
| **Plugins** | Inspect sources, versions, and errors; install optional plugins from repositories or local directories, upgrade, or remove them; disabling built-ins requires risk confirmation |
| **Core Engine** | Download compatible versions, select a source, and switch; the desktop and Harness core update separately |

Do not delete a profile or core as the first troubleshooting step. Copy logs first and determine whether the issue concerns dependencies, a plugin, the service, or a model.

See [Profiles and cores](./profiles-and-cores) for version and profile details or [Data, privacy, and security](../help/data-and-privacy) for storage locations.
