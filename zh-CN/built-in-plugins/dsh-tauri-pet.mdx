## 选择与启用桌宠

<Steps>
  <Step title="打开宠物设置">在 Harness 设置中进入宠物分区。Pets 显示预设与本地 Chat 宠物；Codex 显示本地 Codex 宠物和 ZIP 导入入口。</Step>
  <Step title="选择宠物">预设卡片的启用操作会选中并开启桌宠；本地宠物使用选择操作。取消选择会同时关闭已启用的窗口。</Step>
  <Step title="调整或关闭">大小范围为 50–200%。Pets 标签页和包含设置入口的菜单提供启用 / 关闭操作；关闭状态会持久化，重启后不会自动重新开启。</Step>
</Steps>

桌宠根据会话活动显示状态、气泡与移动方向，不代替会话中的授权或确认。

## 拖拽与甩动

- 抓住宠物即可拖动窗口；快速拖动后松手可甩出，缓慢拖动或停顿后松手不一定触发甩动。
- 飞行以当前显示器工作区为边界，包含重力、边缘反弹、落地挤压与摩擦减速；再次抓住宠物可立即停止飞行。
- 这是单个原生桌宠窗口的交互，不提供宠物之间的碰撞；定位与甩动仍受窗口系统限制。

## 资源来源

| 来源 | 如何载入 | 位置或定义 |
| --- | --- | --- |
| 预设 | 直接使用远端配置与媒体，不经过下载、解压或本地安装步骤。 | `src-tauri/resources/manifest.jsonc` 的 `pets.built-in`；条目提供 `config`、`uri`、`ext`、`kind` 和 `size`。 |
| Chat | 查询时读取本地宠物目录，不是固定的预设名单。 | 当前 DSH 数据目录的 `pets` 子目录，默认 `~/.dsh/pets`。 |
| Codex | 查询本地目录，或从 Codex 标签页导入 `.zip`。 | `$HOME/.codex/pets`。 |

进入设置会重新读取清单。无效的本地清单会被跳过；图集错误可能显示占位缩略图，但不能正常载入宠物。ZIP 导入写入 Codex 目录，以清单中的 ID 识别宠物；重复 ID 会被拒绝，而不是覆盖已有宠物。

## 创建自己的宠物

插件提供 `hatch-dsh-pet` Skill，使用独立的 `providerName: dsh-tauri-pet`，不替换其他 Skill provider。

1. 创建入口需要可用的项目工作区，打开或复用空白会话并预填 `/hatch-dsh-pet` 请求；检查草稿后再发送。
2. Skill 按视频素材流程指导 Agent：每个动作生成一段 10 秒绿幕视频，再抠像、归一化并烘焙图集。需要外部 AI 视频工具，以及 Python 3、ffmpeg、numpy、scipy 等素材工具；插件不会自行提供视频生成服务。
3. 最终交付到 `$DSH_HOME/pets/<petId>/`：`pet.json` 加 PNG / WebP 图集。图集为 8 列，支持 v1 的 9 行或 v2 的 11 行；新宠物使用 v2。校验后重新进入设置选择宠物，无需重启。

本地自定义宠物不直接加载视频包；远端视频预设与本地图集是两种资源路径。不要把上游 `dsh-pet` 的视频目录或插件包当成本地 Chat 宠物导入。

<Note>
  沿用上游动画、提示词、源视频或基于它们二创时，须遵守素材禁止商用的限制，并在介绍、展示与分发处附上[上游作者链接](https://github.com/PC2005-cloud/dsh-pet)。代码许可不等于素材许可。
</Note>

## 状态与平台限制

- 启用开关保存在桌面设置中；关闭会销毁窗口。`enabled` 与 `visible` 都由这一开关推导，后者不是独立的实时窗口可见性探测。
- 原生 Wayland 下无法保证桌宠置顶与定位。设置中的 Force XWayland 作用于整个应用，需要重启生效，可能影响缩放与输入法。
- 预设素材需要网络；本地 Chat / Codex 宠物按本地资源载入。

<Warning>
  只使用可信的远端资源与 ZIP 包。Harness 和插件可以执行本地代码、访问本地文件；Profile 不是操作系统沙箱。
</Warning>

## 客户端桥

状态与选择使用 `get_pet_status`、`set_pet_enabled`、`set_active_pet` 和 `set_pet_size`；资源使用 `list_pets`、`list_preset_pets`、`get_pet_asset` 和 `import_pet`。原生命令经桌面白名单桥执行，不提供普通浏览器的原生窗口保证。
