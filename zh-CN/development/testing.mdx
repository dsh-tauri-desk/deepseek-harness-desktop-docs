开发期间运行最快的相关检查；提交 Pull Request 前按修改范围补齐真实进程与平台测试。

## JavaScript 检查

首次检出先准备 workspace 构建产物；依赖与 E2E 准备步骤见 [CI 工作流](https://github.com/dsh-tauri/deepseek-harness-desktop/blob/main/.github/workflows/ci.yml)。

```bash
pnpm build:plugins
pnpm typecheck
pnpm lint
node node_modules/vitest/vitest.mjs run --project unit
```

| 脚本 | 测试范围 | 额外准备 |
| --- | --- | --- |
| `test:unit` | Vitest 单元与组件测试 | 共享包与插件构建产物 |
| `test:e2e:plugin` | L2：真实 Harness 与 Chromium | 插件产物、Chromium、独立 Harness 运行时 |
| `test:e2e:desktop` | L3：真实 Tauri 窗口与 WebDriver | 嵌入前端的 Debug 二进制；当前 CI 在 Windows 运行 |

按仓内测试协议显式使用 `run`，例如：

```bash
node node_modules/vitest/vitest.mjs run --project plugin
node node_modules/vitest/vitest.mjs run --project desktop
```

`pnpm test` 选择全部三个 project，不只是前端单元测试。使用隔离测试目录，让测试管理服务生命周期；不要复用正式版服务。

## Rust 检查

在 `src-tauri/` 中：

```bash
cargo check --locked
cargo test --all-features --locked
```

CI 的 Rust 矩阵为 Ubuntu 22.04、macOS 14 与 Windows；平台依赖与[开发环境](./setup)相同。

## 手动场景

- 安装与恢复：首次下载、中断、重试、本地内核复用及更新失败。
- 服务生命周期：健康检查、端口避让与回落、重启、关闭、日志及正式版/Debug 隔离。
- Profile 与插件：切换 Profile、增删预设或社区插件、恢复内置桥。
- 平台打包：Windows 安装包、macOS 签名/公证验证、Linux `.deb`、AppImage 与 Wayland 冒烟测试。

## 提交 Pull Request 前

- 为行为变化新增或更新测试。
- 确认未提交密钥、本机隐私路径或生成的应用数据。
- 涉及路径或端口时同时测试正式版和 Debug。
- 用户可见变化需同步两种文档语言。
