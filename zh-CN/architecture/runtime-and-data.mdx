桌面壳将托管应用依赖与 Harness 用户数据分开，以支持内核更新和开发构建而不混用 Profile 状态。

## 运行时选择

| 项目 | 当前值 |
| --- | --- |
| 桌面版本 | `0.22.1`（正式版）；最新预览版为 `0.20.1-beta.4` |
| Harness 内核 | 推荐 `0.2.0-rc.2`；当前清单与本地 CLI 校验最低值为 `0.1.5-rc.1` |
| 托管环境 | Node.js `v22.22.0`、pnpm `11.7.0` |

- 最低内核版本不是所有插件的兼容性保证。
- 复用兼容的本地工具；缺失或原生模块 ABI 不兼容时可回退托管副本。
- 托管内核来自 [deepseek-harness-pkg](https://github.com/dsh-tauri/deepseek-harness-pkg)，优先官方 GitHub 资源，失败时尝试镜像。
- 版本以[运行时清单](https://github.com/dsh-tauri/deepseek-harness-desktop/blob/main/src-tauri/resources/manifest.jsonc)为准。

## 数据目录迁移

非 Debug 构建可在**配置 → 数据**中更改数据目录；Windows 安装器也可选择位置。

- 迁移依次执行复制、校验（文件数与字节数）、把旧目录改名为 `<旧目录>.moved-<时间戳>`，最后重写用户级 `DSH_HOME`；不会删除原数据。
- 先完成任务并关闭使用相同目录的其他客户端；桌面端会停止本机 Harness 后迁移。校验不完整会报 `DATA_DIR_COPY_INCOMPLETE`。
- 可回滚；若当前目录非空，会先改名为 `<目标目录>.current-<时间戳>`。
- 开发构建固定使用 `~/.dsh.dev` 并忽略 `DSH_HOME`，因此不能迁移数据目录。
- 更改后已打开的终端需要重启才能使用新路径。

## 正式版与 Debug 隔离

`<AppData>` 表示当前用户的应用数据目录；下表列出默认路径。每个 Profile 位于数据根下的 `profiles/<id>/`。

| 内容 | 正式版 | Debug |
| --- | --- | --- |
| 默认端口 | `3080` | `3081` |
| Harness 数据根 | 非空 `DSH_HOME`，否则 `~/.dsh` | 强制 `~/.dsh.dev`，忽略继承的 `DSH_HOME` |
| 托管 Node | `<AppData>/runtime/` | `<AppData>/dev/runtime/` |
| 默认托管内核 | `<AppData>/dependencies/dsh/` | `<AppData>/dev/dependencies/dsh/` |
| 托管依赖 | `<AppData>/dependencies/` | `<AppData>/dev/dependencies/` |
| 设置存储 | `.store.dat` | `.store.dev.dat` |
| 服务日志 | `<AppData>/logs/dsh-web.log` | `<AppData>/dev/logs/dsh-web.dev.log` |
| CLI PATH 修改 | 默认启用，可在设置关闭 | 不修改用户 PATH，也不覆盖正式版 `dsh` shim |

## 端口行为

服务绑定 `127.0.0.1`。首选端口被占用时可选择更高的空闲端口，并把最终 URL 返回桌面客户端；
端口恢复空闲后，后续启动可回到首选值。

## 命令行集成

正式版默认启用 `dsh` / `pnpm` shim，可在设置关闭。Windows 注册用户级 PATH；Unix 在 `~/.zshrc` 与 `~/.bashrc` 中维护自己的标记块，不覆盖其他配置。重新打开终端后使用。

<Warning>Harness 与插件可使用用户权限执行本地代码。Profile 和 Debug 目录隔离不是操作系统沙箱。</Warning>
