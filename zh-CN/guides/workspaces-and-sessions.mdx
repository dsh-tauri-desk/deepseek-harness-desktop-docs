工作区是任务操作的目录，会话保存对话与工具活动。发送任务前确认路径和分支，明确允许修改的范围。

## 启动会话

<Steps>
  <Step title="选择工作区">打开目标仓库或目录，确认显示的路径；Git 功能需要系统已安装 Git。</Step>
  <Step title="创建会话">选择模型，说明预期结果、禁止操作和验证方式。一个会话尽量只处理一个明确目标。</Step>
  <Step title="审查执行结果">检查工具活动、文件 diff 和测试结果，再决定是否提交、发布或保留更改。</Step>
</Steps>

## 用 Worktree 分离并发更改

内置 [Worktree 集成](../built-in-plugins/dsh-tauri-worktree)可为任务创建独立 Git 工作树和分支，不在主检出目录直接写入更改。

1. 明确请求在工作树中完成任务。
2. 在隔离会话中检查 diff、验证结果和未提交状态。
3. 需要带回本地仓库时，明确批准检出并指定目标分支。

<Warning>
  任务完成或 PR 合并不代表已授权检出。检出会移除隔离工作树；先提交需要保留的工作，暂存改动需要选择携带。未暂存和未跟踪文件不能假定会自动带回。
</Warning>

会话归档用于整理历史，见[会话归档](../built-in-plugins/dsh-tauri-archive)；它不等于保存工作树中的所有未提交更改。

## 安全边界

- 工作区路径不是权限沙箱；以实际工具权限和审批为准。
- Git 工作树分离分支与文件，不隔离进程、网络或凭据。
- 档案分离配置与插件环境，不应视为独立的会话数据空间。
- 不要把密钥放进提示、源码或公开日志；把生成的命令当作需要审查的代码。

处理不可信仓库时使用真正的操作系统隔离。数据位置和备份范围见[数据、隐私与安全](../help/data-and-privacy)。
